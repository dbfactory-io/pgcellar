SSH key

pgCellar owns one ed25519 key pair, in the .ssh directory of the barman user (the private key stays there, mode 0600, and is never shown). It is used to reach the PostgreSQL servers over SSH: rsync backups, and the connection test. WAL shipping uses a second, opposite trust, explained below.

Set up WAL shipping on a PostgreSQL server

WAL shipping means PostgreSQL pushes every finished WAL file to pgCellar's Barman with archive_command (Barman option archiver = on). Choose the WAL method archive_command or both in the server form first. Then, on the PostgreSQL server:

Prerequisite: PostgreSQL pushes the WAL files over SSH, so the pgCellar host must run an SSH server that the PostgreSQL servers can reach, with the barman user allowed to log in by key. The pgCellar Docker image contains an SSH client only; publish the port of an SSH server that shares the Barman data volume, or use WAL streaming.

  1. The SSH trust, in the right direction.
    • WAL shipping (PostgreSQL to pgCellar): barman-wal-archive runs as the postgres user and connects to barman@{{.Key.Host}}. So the key of the postgres user of the PostgreSQL server goes into authorized_keys of the barman user on the pgCellar host (~barman/.ssh/authorized_keys). Create a key for postgres if it has none: sudo -u postgres ssh-keygen -t ed25519.
    • Backups with rsync, the connection test, and Barman's checks (pgCellar to PostgreSQL): Barman connects to the PostgreSQL server as the user of ssh_command (usually postgres@db1). So the public key above goes into ~postgres/.ssh/authorized_keys on the PostgreSQL server: 
      sudo -u postgres mkdir -p ~postgres/.ssh && sudo -u postgres chmod 700 ~postgres/.ssh
echo '{{.Key.PublicKey}}' | sudo -u postgres tee -a ~postgres/.ssh/authorized_keys
sudo -u postgres chmod 600 ~postgres/.ssh/authorized_keys
    The first connection also needs the host key of the server in the known_hosts of the barman user: connect once by hand as that user (ssh postgres@db1 true, answer yes), because the tests here run with BatchMode and cannot ask.
  2. Install barman-cli on the PostgreSQL server (package from PGDG or the Barman repository): it provides barman-wal-archive.
  3. Turn archiving on in postgresql.conf (or with ALTER SYSTEM), replacing <server> with the name of the server in pgCellar: 
    archive_mode = on
archive_command = 'barman-wal-archive {{.Key.Host}} <server> %p'
    archive_mode needs a restart of PostgreSQL; SELECT pg_reload_conf(); is not enough for it. archive_command alone can be reloaded.
  4. Check. Close a WAL file and look at it arriving: barman switch-wal --archive <server> (the Switch WAL button of the server page does it), then barman check <server> (Run check now). The Server setup section of the server page tells what is still wrong.
